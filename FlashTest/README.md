# FlashTest — 外部 SPI Flash 扇区安全测试工程----已确认flash从低地址开始写

用来查清楚外挂的 **SST25VF016（2MiB）** 里**哪些扇区可以安全读写**。----已确认最后两个扇区安全，用户注意不要放过多历史版本bin文件进去

## 为什么需要它

Luby 用户文档写着：控制器插 USB 后会显示一个 **1M 大小的 U 盘**，把 `.bin` 拷进根目录
就完成下载。而外挂 flash 正好是 **2MiB** —— **那个 U 盘很可能就建在同一颗芯片上**。

如果真是这样，**bootloader 就住在这颗 flash 里**，"写在最末尾"就不一定安全。
在搞清楚它占了哪些扇区之前，标定工程不能往 flash 里写任何东西。

## 分相设计

### Phase 1 — 只读普查（上电自动执行，**零写入**）

1. **ID 稳定性**：JEDEC ID 连读 1000 次，统计不一致次数。
   不一致说明 bootloader 跳转瞬间 SPI2 停在半途，或者 HOLD# 悬空被噪声影响。
2. **状态寄存器**：记录 BUSY/WEL/BP3..0/BPL 的实际上电值 ——
   回答"器件上电是否默认全阵列保护"这个关键问题。
3. **选项字节**：读 `FLASH_OBR` 看是软件狗还是硬件狗。
   **只读绝不写** —— 写选项字节期间掉电会把板子变砖。
4. **整片扫描**：512 个 4KB 扇区逐个分类（2MiB @4.5MHz 约 4 秒）。
5. **LCD 分页地图** + 串口（UART5, 115200）逐扇区明细输出。

### Phase 2 — 破坏性写测（**必须按住 KEY2 开机 3 秒**）

- 只测 Phase 1 判为"全 0xFF"的扇区，**从最后一个往前走**，遇到第一个非空的就停。
- 一个本来就全 0xFF 的扇区，擦除它**零信息损失**（擦完还是全 0xFF），
  所以"擦 → 写图案 → 回读比对"是内容保持的；测完再擦回 0xFF 恢复原状。
- 顺带实测并打印 **4KB 擦除耗时**与单字节编程耗时 —— 这两个数决定看门狗余量。
- 任何非 0xFF 且不是我们记录的扇区，**一律不碰**。

## 屏幕怎么看

```
P1/11 0x000000      ← 第几页 / 共几页 / 起始地址
................    ← 每格一个扇区
....FFFFBBBB....    ← 3 行 x 16 = 48 个扇区/页
...........CC.
```

| 字符 | 含义 |
|---|---|
| `.` | 全 0xFF（空扇区，可以安全使用） |
| `#` | 有数据，认不出是什么 |
| `C` | 我们的标定记录 |
| `F` | 文件系统（MBR / FAT / NTFS / exFAT 签名） |
| `B` | 固件镜像（看起来像 STM32 的 .bin） |
| `?` | 读失败 |

**KEY1（下键）下一页，KEY2（上键）上一页。**

## 怎么用它回答"哪些扇区安全"

1. 只烧本工程，看 Phase 1 的地图 —— **`. ` 是空的，`F`/`B`/`#` 是被占的**。
2. 重点看最后几个扇区（`P11` 那页）：如果 `0x1FF000` / `0x1FE000` 是 `.`，
   说明标定工程按现在的位置写是安全的。
3. 再做**标记实验**确认 U 盘到底在不在片内：
   往候选扇区写标记 → 断电 → 按住 BACK 进 U 盘模式 → 拷一个 `.bin` 进去 →
   重新上电 → 复读那个标记。**标记没了 = bootloader 确实在用这个扇区。**
4. 确认之后再改 `cal_store.h` 里那三个地址宏，重新编译标定工程与主工程。



## 与其他两个工程的关系

本工程与 `car7.15`、`CalibTool` 共用四对模块（`sst25.*` / `sst25_port.*` /
`cal_store.*` / `iwdg.*`），代码**逐字节相同**。唯一差异是本工程的
`Core/Inc/sst25_port.h` 顶部把擦写窗口放宽到了整片 —— 否则连扇区 0 都碰不到。

放宽窗口不等于放弃保护：真正的防线是 `cal_store.c` 的**扇区内容分类**
（文件系统/固件镜像一律硬拒绝）加上 Phase 2 必须**人工按住 KEY2** 才进入。
